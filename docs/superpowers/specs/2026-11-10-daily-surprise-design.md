# 《喜从天降（Daily Surprise）》设计文档

- 日期：2026-11-10
- 状态：需求已与作者逐条确认，待评审后进入开发计划
- 项目：`E:\Game\Mod\survivallog-mods\DailySurprise`
- 游戏：《生存日志 Survival Log》（Unity 6000.2.7f2 / IL2CPP / BepInEx 6 + HarmonyX）
- 命名：目录与程序集 `DailySurprise`，显示名 **喜从天降**，GUID `com.local.survivallog.dailysurprise`（命名与 GUID 为代理裁量，可改）

## 1. 意图与定位

每个游戏日睡醒时，随机降临一个"天降事件"：可能是好运（物资、buff），可能是霉运（debuff、建筑受损），也可能平平无奇。原生事件卡弹窗（配图 + 台词，部分带选项），奖励/惩罚即时送达。给重复的生存日常加"每天开箱"的期待感，整体基调**偏奖励、黑色幽默生活流**。

## 3. 目标 / 非目标 / 反目标

**目标**
- 45 个事件（平淡 5 / 好运 22 / 霉运 18），每事件 1 套台词 + 1 张配图 + 明确效果
- 仅灾后模式生效（普通档+无尽档），灾前序章完全静默
- 两层概率：先掷运势档（好/平/霉），档内再按稀有度分层
- 5 预设难度 + 自定义难度，档间差异显著（频率、稀有度分布、奖励/损失倍率三轴拉开）
- 防劝退机制：霉运保底、永久负面上限、灾厄限次、同事件防连抽
- cfg 热更；BepInEx 侧自持数据，不碰游戏存档结构

**非目标（v1 不做）**
- 自绘 WebUI 全屏剧情卡
- 指定小时触发（留 v2：`TriggerMode=Hour`）
- 一日多事件、事件链/连续剧情
- 与其他 mod 联动
- 玩家可编辑的事件 JSON（事件定义在代码常量里，理由见 §7.3）

**反目标（做了即失败）**
- 永久惩罚刷屏劝退（上限+频率红线失效）
- 弹窗剧情与 buff 悬浮说明互相穿帮
- 污染游戏存档、与其他套件 mod 冲突（ID 段、表注入竞态）
- 不可预期的 buff 叠加穿透

## 4. 单位与术语（已对 gamekb 实证）

属性官方名称：**饱腹 Satiety / 心态 Morale / 精力 Stamina / 健康 Health / 生命 Vitality**。

| 字段类型 | 语义 | 换算 |
|---|---|---|
| `BuffInterval`（秒） | 周期结算间隔 | 3600=每1小时，7200=每2小时，10800=每3小时，14400=每4小时，86400=每24小时 |
| `BuffDuring`（秒） | 时长 | 43200=12小时，86400=24小时，432000=5天，**−1=永久** |
| `*Add` / `*Del` | **比例小数** | 0.5=50%，0.2=20%，−0.3=−30%，−0.005=−0.5% |
| `*Interval` | 每周期绝对点数 | 如 每2小时心态−3 |
| `*Max` / `BuffSpeed` | 绝对点数 / 比例 | 精力上限−20；移速+30% |

**相同 buff 重复获得**：引擎按 `Overlay` 字段处理（5 种模式）。本项目用到的全部 buff 一律 `Overlay=0` = **时长叠加、强度不变**（例：连续两天感冒=48 小时感冒，痛苦不翻倍；永久 buff 重复获得=无变化）。自注入行同样固定 `Overlay=0`。

## 5. 核心机制

### 5.1 触发流程

```
新一天结算（CaptureDaySnapshot postfix，同日幂等 + DayWatcher 兜底轮询）
 → 查 StateStore：今日已触发？（是→跳过）
 → 保底检查：连续霉运达 N 天 → 强制好运档
 → 第一层：掷 好运/平淡/霉运（难度表三轴概率）
 → 第二层：档内掷稀有度层
 → 层内等权选事件（防连抽：与昨日同事件则重掷一次）
 → 资格过滤：事件不满足前置条件（无对应家具/背包无生鲜/零件不足等）→ 同层重掷；整层无资格 → 降一层重掷（轻度层全部以自身为对象，恒有资格）
 → 原生事件卡弹窗（台词+配图，可选选项）
 → 发放：RewardSet 声明式 / 代码直调（耐久、属性、腐坏、扣件）
 → StateStore 记账（lastDay、badStreak、permNegativeUsed、grantedPerms…）
```

### 5.3 自定义难度（档 6）

cfg 项：`CustomGoodPercent=45`、`CustomPlainPercent=25`、`CustomBadPercent=30`（默认即档 3；**和必须=100**，非法→日志警告并回退档 3）、`CustomRewardMultiplier=1.0`、`CustomLossMultiplier=1.0`（范围 0.1~5.0）。

- 内层稀有度分布、保底（3 天）、永久负面上限（1）、灾厄开放性：跟档 3
- 允许 霉运=0（纯抽奖模式）或 好运=0（自虐模式）
- 暴露损失倍率是代理裁量（作者原话只点了概率与奖励倍率；缺它自定义档只调半边）
- 命运眷顾/行运低潮变体授予规则：**预设档 1~5 固定授予同号变体（档N→变体N）；仅自定义档按倍率映射**——奖励倍率 ≥1.75→Ⅰ、≥1.25→Ⅱ、≥0.875→Ⅲ、≥0.625→Ⅳ、否则Ⅴ；损失倍率 ≥1.75→Ⅴ(−4%)、≥1.25→Ⅳ(−3%)、≥0.75→Ⅲ(−2%)、否则Ⅱ(−1%)
- 自定义档取代了早期设想的"霉运一键关"开关（把霉运设 0 即可）

### 5.4 防劝退规则

- **保底**：连续 N 天霉运 → 第 N+1 天强制好运（N=难度表值；档 5 无保底）
- **永久负面上限**（每存档计数）：含永久负面的事件 H1/D1/D3 各计 1 次；达上限后自动替换为非永久替补：H1→H4 重病、D1→D2 雷击、D3→H2 管道爆裂。`AllowPermanentNegative=false` 时全部走替补
- **灾厄层**在档 1/2 权重为 0（不出现）
- **灾厄限次澄清**（代理裁量）：灾厄层**无独立次数上限**；"限次"指其中的永久负面部分——D1/D3 计入永久负面上限、达上限走替补，D2 雷击可重复出现（频率由档位权重控制，档 5 约 28 天一遇）。`disasterCount` 仅为统计字段
- **霉运落空处理**（代理裁量）：M1/M3/M4/H2/D2/H3 依赖玩家资产（家具/生鲜/零件），事件带前置条件谓词——无资格→同层重掷，整层无资格→降一层（重度→中度→轻度）。开局空屋等极端情况下霉运自然弱化，属预期行为；H3 追丢线要求持有铁制零件≥10，否则整事件视为无资格
- **防连抽**：与昨日相同事件 → 重掷一次（仍同则接受）
- 平淡档弹窗可用 `ShowPlainPopup=false` 静音

### 5.5 倍率缩放规则

- 奖励倍率 → 物品数量（四舍五入，下限 1）
- 损失倍率 → 耐久百分比、被偷数量、属性损失点数
- buff/debuff **时长与数值不随倍率缩放**（狠度由频率+稀有度分布+损失量表达；永久 buff 用固定 5 变体实现档位差）
- 命运眷顾/行运低潮按 §5.3 的映射选预注入变体，不做动态数值

## 7. 技术方案

### 7.1 选型记录（approaches）

**弹窗管线**：
- A（选定）原生事件表注入：`Config_Event`+`Config_RewardSet` 自定义行 + `DynamicEventManager.TryForceTriggerEvent` 拉起。台词/图/选项/奖励全声明式，白嫖原生弹窗动画与选项 UI；EndlessGuard 五表注入先例。代价：弹窗样式受原生约束。
- B（弃）WebUI 自绘全屏剧情卡（RailUi 样板）：自由度最高，但 UI/回调/图片全套自建，工期约×3，v1 无必要。
- C（弃）混合：双份复杂度。

**每日时点钩子**：
- A（选定）`GameSaveManager.CaptureDaySnapshot(int day)` Harmony postfix + 同日幂等 + 轮询兜底（SaveMgr 实证）。
- B（弃）订阅 `DynamicEventManager.OnDayChanged`：分发顺序不可控。
- C（弃）纯 ticker 轮询：延迟感、幂等复杂。

**事件定义载体**：
- A（选定）代码内静态常量（EventCatalog），注入器负责落到 Config_* 表。利于单测与版本一致。
- B（弃）外置 JSON：玩家可改，但引入装表顺序、校验、热更复杂度，与"不暴露单事件"的产品定位矛盾。

1. **`TryForceTriggerEvent` 对注入行的完整链路**：弹窗样式字段（PopUpType/KeepTime/Icon 相对路径）、选项（ChoseName_Local/ChoseID 数组的 IL2CPP 类型映射）、StartRewardSet 自动发放是否生效。（静态核对：`EventDes_Local` 可直接写裸中文）
2. **RewardSet 能力边界**：静态核对已确认具备 `AttriKeyChange`/`ItemCost`/`AddBuff`/`RandomGroup` 声明式能力（builder check）；实机发放路径与负向数值仍需验证，异常则走代码路径（架构已预留双通道）
3. **与原生每日事件的并存**：原生事件照常触发时是否造成同日双弹窗轰炸；如是，v1 加"延迟/排队"策略再调优
4. **表注入竞态**：ConfigManager.Initialize 重建窗口的哨兵复查节奏
5. **数值实机校准**：物品数量初稿按实机经济微调（不改结构）
6. **永久属性直改**：`AttributeComponent` 直改基础值在保存/读取后不被覆盖的实证
7. **模式门控**：`WorldStateType` 枚举值与灾前/灾后/无尽的映射实证；注入行 EndlessMode/DemoTwoMode 字段按生效范围取值；实机测试矩阵=灾后普通档+无尽档两套
