## 2. 命名合规（自动校验）

规则：文件名 = `ds_` + 事件号小写 + `.webp`，全小写字母数字（如 `ds_g1.webp`）；不多、不少、不拼错。

**自动对账**：仓库根目录运行

```
sdk\dotnet\dotnet.exe test SurvivalLog.DailySurprise.Tests/SurvivalLog.DailySurprise.Tests.csproj
```

测试套件中的 `IconNamingTests` 会直接扫描 `SurvivalLog.DailySurprise\Art\` 目录：

- 命名不合规、目录外多余 webp（越集）、WebP 文件头不符（png/jpg 改名货）→ **测试红**；
- 缺图只报告不判红（正式图逐张到位过程中不阻塞开发）；
- 唯一硬要求：`ds_g1.webp` 必须在（链路验证占位）。

## 3. 分辨率与格式统一

- ☐ 45 张全部 **1536×1152（4:3 横版）**（或统一 2048×1536 出图后统一缩到 1536×1152，交付时同尺寸）。
- ☐ 全部 WebP 格式、质量 90 左右（非 PNG/JPG 改名货）。
- ☐ 快速核对方法：全选 → 看属性里尺寸是否一致；或 `Art\` 里右键排序按大小，异常小的文件点开看。

## 4. 风格一致性人工过目（抽 5 张并排）

并排放在一张大图里对比（拼图工具或 PPT 皆可），至少覆盖五个段位：

- ☐ 抽样建议：`ds_n3.webp`（平淡）、`ds_g1.webp`（好运普通）、`ds_r3.webp`（好运稀有）、
  `ds_h1.webp`（霉运重度）、`ds_d2.webp`（灾厄）。
- ☐ 色调一致：都是中低饱和+冷暖对撞布光（暖主光/青灰紫冷影），没有一张突然荧光。
- ☐ 笔触一致：都是日式动画背景美术同一种笔触，没有混入照片风/3D 风/Q 版。
- ☐ 光线一致：暖色主光源（黄昏橙金/晨光/室内暖灯）对比冷阴影，没有硬闪光灯感。
- ☐ 主体大小一致：图标缩小后主体占比接近，没有一张是大远景、一张是特写。
- 不满足 → 回 `prompt-template.md` §4 的一致性技巧（固定 seed / 垫参考图）重出该张。

## 5. 落盘路径与实机验证

链路说明（全自动，无需手动拷图）：`Art\` 里的图在**构建时**打包进插件 DLL；游戏启动时
`IconDrop` 自动把它们写到 `<游戏根>\SurvivalLog_Data\StreamingAssets\WebUI\Res\Icon\`
（已存在且内容一致则跳过；换图后重新构建启动即覆盖）。结果记录在
`BepInEx\plugins-data\DailySurprise\trace\icons.txt`。

验证步骤：

1. ☐ 图放入 `Art\` → 构建一次 → 部署插件 → 启动游戏。
2. ☐ 查 `trace\icons.txt`：有 `Install 完成：内嵌图标资源 N 张` 行（现在 N=1；45 张齐后 N=45）。
3. ☐ 进档，cfg 设 `DebugForceEventId = 99205`（G1）→ 事件卡图标显示为**粉色纯色块**=链路通
   （占位图；若显示裂图/灰块 → 按 §5 故障排查）。
4. ☐ 正式图到位后：同法逐张抽查——把 `DebugForceEventId` 设为上表"强制抽查用 Id"列的值，
   进档看弹出的对应事件卡图标是否为该事件新图（抽查无暇全看时，至少过一遍 45 个 Id）。
5. ☐ 换图热更验证：替换 `Art\ds_g1.webp` 为正式图 → 重新构建部署 → 重启游戏 → 图标自动换成新图。

故障排查：

- 裂图：`icons.txt` 若有 `WebUI/Res 目录不存在` → 游戏目录结构异常（重装/校验游戏文件）；
  若有 `落盘失败` → 看具体异常信息（多为权限/杀软拦截）。
- 显示旧图：`WebUI\Res\Icon\ds_xx.webp` 被外部占用或只读；删除该文件重启游戏即重落。
